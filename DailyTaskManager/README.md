# DailyTaskManager

# معرفی پروژه
این پروژه یک سامانه مدیریت وظایف است که با هدف ایجاد، مشاهده، ویرایش، حذف و مدیریت وظایف روزانه طراحی شده است ..
این پروژه شامل یک بخش بک‌اند بر ای‌اس‌پی‌دات‌نت کور وب ای‌پی‌آی و یک رابط کاربری ساده با استفاده از اچ‌تی‌ام‌ال، سی‌اس‌اس و جاوااسکریپت است. اطلاعات وظایف در پایگاه داده مای‌اس‌کیو‌ال ذخیره می‌شوند و ارتباط میان رابط کاربری و بخش بک‌اند از طریق رابط برنامه‌نویسی کاربردی و با استفاده از داده‌های جیسون انجام می‌شود.
امکانات اصلی پروژه شامل مدیریت کامل وظایف، جستجو بر اساس عنوان، فیلتر بر اساس وضعیت انجام وظیفه، مرتب‌سازی بر اساس معیارهای مختلف، تعیین اولویت، تعیین تاریخ سررسید و صفحه‌بندی نتایج است.
همچنین برای افزایش کیفیت و پایداری پروژه، اعتبارسنجی ورودی‌ها، مدیریت خطاهای عمومی، استفاده از کدهای وضعیت مناسب اچ‌تی‌تی‌پی و تست واحد برای بخش‌های اصلی پروژه در نظر گرفته شده است

# نصب و اجرا
دریافت پروژه
ابتدا کد پروژه را دریافت کرده و آن را در محیط توسعه مورد نظر باز کنید.
ایجاد پایگاه داده
ابتدا پایگاه داده‌ای با نام DailyTaskManager در مای‌اس‌کیو‌ال ایجاد کنید.
سپس ساختار جدول‌های مورد نیاز پروژه را با استفاده از فایل اسکریپت پایگاه داده موجود در پروژه ایجاد کنید.
تنظیم اطلاعات اتصال به پایگاه داده
اطلاعات اتصال به پایگاه داده در بخش یوزر سیکرتس قرار گرفته است و اطلاعات حساس در فایل‌های پروژه قرار داده نشده‌اند.
برای اجرای پروژه باید اطلاعات مربوط به اتصال به پایگاه داده، از جمله نام سرور، نام پایگاه داده، نام کاربری و رمز عبور، در یوزر سیکرتس تنظیم شوند.
نصب پکیج‌ها
پس از باز کردن پروژه، پکیج‌های مورد نیاز پروژه را دریافت و نصب کنید.
اجرای پروژه
پس از انجام تنظیمات بالا، پروژه را اجرا کنید.
پس از اجرای موفق پروژه، بک‌اند اجرا شده و رابط کاربری نیز از طریق آدرس اجرای پروژه قابل دسترسی خواهد بود.

# نحوه ایجاد پایگاه داده و اجرای اسکریپت
ابتدا یک پایگاه داده با نام DailyTaskManager در مای‌اس‌کیو‌ال ایجاد کنید.
سپس فایل اسکریپت پایگاه داده پروژه را در مای‌اس‌کیو‌ال ورک‌بنچ اجرا کنید تا جدول‌ها و ساختار مورد نیاز پروژه ایجاد شوند.
در این پروژه از Migration برای ایجاد پایگاه داده استفاده نشده و ساختار پایگاه داده از طریق SQL Script ایجاد می‌شود.

# نحوه اجرای بک‌اند و فرانت‌اند
پس از دریافت پروژه و انجام تنظیمات پایگاه داده و یوزر سیکرتس، پروژه را در ویژوال استودیو باز کرده و اجرا کنید.
با اجرای پروژه، بخش بک‌اند و رابط کاربری به صورت همزمان اجرا می‌شوند.
رابط کاربری پروژه در پوشه مربوط به فایل‌های استاتیک قرار دارد و از طریق آدرس اجرای پروژه قابل دسترسی است.
پس از اجرای موفق پروژه، می‌توان از طریق رابط کاربری با سامانه کار کرد و درخواست‌های مربوط به مدیریت وظایف به بک‌اند ارسال می‌شوند.

# معرفی نقاط پایانی رابط برنامه‌نویسی
| متد      | مسیر              | توضیح                                                                 |
| -------- | ----------------- | --------------------------------------------------------------------- |
| `POST`   | `/api/Tasks`      | ایجاد یک وظیفه جدید                                                   |
| `GET`    | `/api/Tasks`      | دریافت فهرست وظایف همراه با امکان فیلتر، جستجو، مرتب‌سازی و صفحه‌بندی |
| `GET`    | `/api/Tasks/{id}` | دریافت اطلاعات یک وظیفه بر اساس شناسه                                 |
| `PUT`    | `/api/Tasks/{id}` | ویرایش اطلاعات یک وظیفه                                               |
| `DELETE` | `/api/Tasks/{id}` | حذف یک وظیفه                                                          |

 پارامترهای دریافت فهرست وظایف
برای دریافت فهرست وظایف می‌توان از پارامترهای زیر استفاده کرد:
* `isCompleted` برای فیلتر بر اساس وضعیت انجام وظیفه
* `search` برای جستجو بر اساس عنوان
* `sort` برای مرتب‌سازی
* `page` برای تعیین شماره صفحه
- `newest` برای نمایش جدیدترین وظایف
- `oldest` برای نمایش قدیمی‌ترین وظایف
- `priority` برای مرتب‌سازی اولویت از بالا به پایین
- `priorityAsc` برای مرتب‌سازی اولویت از پایین به بالا
- `dueDate` برای نمایش نزدیک‌ترین تاریخ سررسید

# تصمیمات طراحی پایگاه داده و ساختار پروژه
تصمیمات طراحی پایگاه داده
پایگاه داده پروژه با استفاده از مای‌اس‌کیو‌ال طراحی شده و برای ذخیره اطلاعات وظایف از جدول tasks استفاده شده است.
برای هر وظیفه یک شناسه یکتا در نظر گرفته شده که به صورت خودکار افزایش پیدا می‌کند.
عنوان وظیفه و توضیحات دارای محدودیت طول هستند تا از ورود اطلاعات بیش از حد مجاز جلوگیری شود.
وضعیت انجام شدن وظیفه به صورت مقدار بولی ذخیره شده است و برای تعیین اولویت، مقادیر مربوط به اولویت‌های کم، متوسط و زیاد در نظر گرفته شده است.
تاریخ سررسید به صورت اختیاری در نظر گرفته شده و تاریخ ایجاد و آخرین ویرایش وظیفه نیز در پایگاه داده ذخیره می‌شوند.
در این پروژه از میگریشن برای ایجاد ساختار پایگاه داده استفاده نشده و ساختار پایگاه داده از طریق اسکریپت ایجاد می‌شود.
ساختار پروژه
ساختار پروژه به صورت لایه‌بندی شده طراحی شده است تا مسئولیت بخش‌های مختلف از یکدیگر جدا باشند.
بخش کنترلرها برای دریافت درخواست‌ها و ارسال پاسخ‌ها
بخش سرویس‌ها برای پیاده‌سازی منطق مربوط به مدیریت وظایف
بخش مدل‌ها برای تعریف ساختار موجودیت‌های پایگاه داده
بخش انتقال داده برای تعریف داده‌های ورودی و خروجی
بخش داده برای ارتباط با پایگاه داده
بخش استثناها برای مدیریت خطاهای عمومی
بخش شمارش‌ها برای تعریف مقادیر ثابت مانند اولویت وظایف
بخش رابط کاربری برای نمایش و مدیریت وظایف
بخش تست‌ها برای بررسی عملکرد بخش‌های مختلف پروژه
